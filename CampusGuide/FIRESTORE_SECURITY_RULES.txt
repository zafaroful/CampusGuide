================================================================================
RULES OVERVIEW
================================================================================

These rules implement the following security model:

1. PUBLIC DATA (Anonymous Read-Only):
   - locations: All users can read
   - events: All users can read
   - buildings: All users can read

2. AUTHENTICATED DATA (Signed-in Users):
   - users/{uid}/favorites: Only the user can read/write their own favorites

3. ADMIN DATA (Trusted Administrators Only):
   - locations (write): Admin users only
   - events (write): Admin users only
   - buildings (write): Admin users only

4. USER PREFERENCES (Private):
   - users/{uid}/notifications: Only the user can read/write
   - users/{uid}/settings: Only the user can read/write

================================================================================
FIRESTORE SECURITY RULES - TO DEPLOY
================================================================================

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

	// Helper function to check if user is authenticated
	function isAuthenticated() {
	  return request.auth != null;
	}

	// Helper function to check if user is admin
	// Note: Requires custom claims set via Firebase Admin SDK
	function isAdmin() {
	  return isAuthenticated() && 
			 request.auth.token.get('isAdmin', false) == true;
	}

	// Helper function to check if user owns the document
	function isOwner(uid) {
	  return isAuthenticated() && request.auth.uid == uid;
	}

	// LOCATIONS COLLECTION
	// Public read, admin write only
	match /locations/{locationId} {
	  allow read: if true;  // Public access
	  allow create, update, delete: if isAdmin();  // Admin only
	}

	// EVENTS COLLECTION
	// Public read, admin write only
	match /events/{eventId} {
	  allow read: if true;  // Public access
	  allow create, update, delete: if isAdmin();  // Admin only
	}

	// BUILDINGS COLLECTION
	// Public read, admin write only
	match /buildings/{buildingId} {
	  allow read: if true;  // Public access
	  allow create, update, delete: if isAdmin();  // Admin only
	}

	// USER DATA COLLECTION
	// Authenticated users can read/write their own data
	match /users/{uid} {
	  allow read, write: if isOwner(uid);

	  // User favorites subcollection
	  match /favorites/{locationId} {
		allow read, write: if isOwner(uid);
	  }

	  // User notifications subcollection
	  match /notifications/{notificationId} {
		allow read, write: if isOwner(uid);
	  }

	  // User settings subcollection
	  match /settings/{settingKey} {
		allow read, write: if isOwner(uid);
	  }
	}

	// ADMIN LOGS (Admin only)
	match /admin/logs/{logId} {
	  allow read, write: if isAdmin();
	}

	// Deny all other access
	match /{document=**} {
	  allow read, write: if false;
	}
  }
}

================================================================================
DEPLOYING RULES
================================================================================

1. Via Firebase Console:
   a. Go to Firebase Console → Firestore Database → Rules tab
   b. Copy the rules above (excluding headers and documentation)
   c. Click "Publish" to deploy

2. Via Firebase CLI:
   a. Install Firebase CLI: npm install -g firebase-tools
   b. Login: firebase login
   c. Create firestore.rules file with rules above
   d. Deploy: firebase deploy --only firestore:rules

3. Via Code (Firebase Admin SDK):
   ```csharp
   using Firebase.Cloud;

   var rules = File.ReadAllText("firestore.rules");
   // Use Firebase Admin SDK to deploy rules
   ```

================================================================================
AUTHENTICATION SETUP
================================================================================

1. Enable Firebase Authentication in Firebase Console
   - Go to Authentication → Sign-in method
   - Enable Email/Password, Google Sign-in, etc.

2. Set Admin Claims (for admin users):
   ```javascript
   // Firebase Admin SDK (Node.js)
   const admin = require('firebase-admin');

   admin.auth().setCustomUserClaims(uid, { isAdmin: true })
	 .then(() => console.log('Custom claims set'))
	 .catch(error => console.log(error));
   ```

3. Verify authentication in code:
   ```csharp
   var user = FirebaseAuth.Instance.CurrentUser;
   if (user != null) {
	   // User is authenticated
	   var uid = user.Uid;
   }
   ```

================================================================================
TESTING RULES
================================================================================

1. Firebase Emulator (Local Testing):
   ```bash
   firebase emulators:start --only firestore
   ```

   Then in your app, connect to emulator:
   ```csharp
   var settings = new FirestoreSettings();
   settings.Host = "localhost:8080";
   settings.SslCredentials = ChannelCredentials.CreateSsl();
   FirestoreDb.Create(projectId, new FirestoreClient(), settings);
   ```

2. Firestore Rules Simulator (Firebase Console):
   - Go to Rules tab → Simulate read/write
   - Test with different authentication states
   - Verify allow/deny for each collection

3. Manual Testing:
   - Anonymous user: Should read locations/events/buildings
   - Authenticated user: Should read/write own favorites
   - Admin user: Should create/update/delete locations
   - Different user: Should NOT access other users' data

================================================================================
SECURITY BEST PRACTICES
================================================================================

1. NEVER expose admin credentials in client code
2. NEVER trust client-side authentication validation
3. ALWAYS validate sensitive operations server-side
4. REGULARLY audit Firestore access logs
5. USE custom claims for role-based access control
6. IMPLEMENT rate limiting for write operations
7. MONITOR suspicious patterns in access logs

================================================================================
COMMON ISSUES & TROUBLESHOOTING
================================================================================

Issue: "Permission denied" when reading locations
→ Ensure locations rules have "allow read: if true"

Issue: "Only authenticated users can write"
→ Ensure user is logged in before write operations
→ Check custom claims for admin operations

Issue: "Users can access other users' data"
→ Verify isOwner() function checks request.auth.uid
→ Ensure match /users/{uid} uses correct uid variable

Issue: "Performance degradation"
→ Add composite indexes for complex queries
→ Implement pagination for large result sets
→ Cache frequently accessed data client-side
